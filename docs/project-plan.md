# 更好的攻略制作器（Better Walkthrough Maker）项目规划

> 状态：已与需求方逐轮确认（设计树走完，本版为终版规划）。
> 日期：2026-xx-xx（首次定稿）

## 1. 产品定位

- **一句话**：面向游戏攻略作者的桌面设计工具，用"模板 + 自由画布"的方式制作攻略配图，导出 PNG 发布到小黑盒等平台。
- **目标用户**：作者本人自用起步，架构上预留开放给其他攻略作者的余地。
- **平台**：Windows 桌面优先（基于 Qt 6，具备跨平台潜力）。
- **核心范式**：混合模式——模板提供初始布局，之后可自由拖拽编辑（Canva 式）。

## 2. 命名与标识

| 项 | 值 |
|---|---|

| 英文名 | Better Walkthrough Maker（工作目录 Better-Walkthrough-Maker） |
| 项目扩展名 | `.bwm`（Better Walkthrough Maker） |

## 3. 核心概念（领域词汇表）

| 概念 | 定义 |
|---|---|
| 项目 | 对应一个游戏，磁盘上是一个 `.bwm` 文件夹，自包含 |
| 攻略 | 项目下的一个攻略（如"出血流装备推荐"），绑定一个模板类型；**一个攻略下可同时包含页面和文章** |
| 页面 | 攻略下的一页，一页 = 一张导出的 PNG（图文攻略） |
| 文章 | 攻略下的一篇 Markdown 文档（文章攻略），支持嵌入图片与引用项目内页面 |
| 组件 | 画布上的元素：图片 / 文本 / 表格 / 形状 / 贴纸 / 背景 |
| 模板 | 页面布局 + 样式的蓝图，按攻略类型分类 |
| 主题包 | 配色 + 字体 + 组件默认样式（美化包的一部分） |
| 素材包 | 装饰素材合集：边框、标题装饰、贴纸、图标（美化包的一部分） |
| 素材库 | 项目内已导入的图片资源（原图复制进项目） |

## 4. 数据模型

### 4.1 项目文件夹结构

```
我的项目名.bwm/
├── project.json          # 项目元信息 + 攻略/页面/组件数据
├── assets/               # 素材原图（导入时复制进项目）
│   └── <素材ID>.png
├── templates/            # 项目内自定义模板（可选）
└── themes/               # 项目内自定义主题（可选）
```

`project.json` 设计要点：

- 纯 JSON，可读、可版本化；文件头带 `formatVersion` 字段，为格式迁移预留。
- 结构：`项目 → 攻略[] → (页面[] → 组件[]) + (文章[])`。
- 组件统一基类字段：`id`、`类型`、`位置(x,y)`、`尺寸(w,h)`、`旋转`、`zOrder`、`可见性`、`锁定`。
- 文章字段：`id`、`title`、`markdown`（正文内嵌，含 `![[W:P]]` 页面引用与 `![](assets/...)` 图片引用）。
- 页面字段：`name`、`width`/`height`、`components`，以及可选的 `backgroundImage`
  （**项目内相对路径**，如 `assets/xxx.png`；作为整页底图，等比覆盖绘制，空则不写该字段）。

### 4.2 组件数据要点

| 组件 | 专属字段 |
|---|---|
| 图片 | 素材引用、裁剪矩形、圆角半径、描边（后期：蒙版、滤镜） |
| 文本 | 内容、富文本样式（字体/字号/颜色/粗斜体/对齐/行距/阴影） |
| 表格 | 行×列、单元格文本、样式（表头/边框/斑马纹/列宽） |
| 形状 | 类型（矩形/圆角矩形/椭圆/线条/箭头）、填充、描边 |
| 贴纸 | 素材包资源引用、缩放 |
| 背景 | 纯色（跟随主题）/ 图片（页面级 `backgroundImage`，等比覆盖铺满）；渐变列为后续 |

### 4.3 文章数据要点

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识（QUuid） |
| `title` | 文章标题 |
| `markdown` | Markdown 正文，内嵌于 `project.json` |

页面引用语法（本项目自定义扩展，标准 Markdown 不支持）：

- `![[W:P]]` —— 引用第 W 个攻略的第 P 个页面，预览与导出时渲染为对应页面的图片。
- 导出 `.md` 时保留原文，同时产出 `images/` 目录与兼容版（引用替换为标准图片语法）。

## 5. 功能模块

### 5.1 项目管理

- 新建项目向导：游戏名、图标、默认画布尺寸、默认主题。
- 打开 / 最近项目列表。
- 项目自包含（素材复制进 `assets/`），整个文件夹可备份、迁移、分发。
- 自动保存 + 崩溃恢复：定时写 `project.json` 快照，重启时提示恢复。

### 5.2 编辑器（画布）

- 画布：缩放（10%–400%）、平移、标尺、参考线、网格吸附。
- 组件操作：拖拽移动、8 手柄缩放、旋转、对齐（左/中/右/顶/底/等距分布）、图层管理（上移/下移/置顶/置底 + 图层面板）、多选、编组、复制克隆（支持跨页面）。
- 撤销 / 重做：命令模式，内存内不限步数。
- 快捷键：Ctrl+C/V/Z/Y、Delete、方向键微调、对齐快捷键。

### 5.3 组件系统

- **图片**：裁剪（自由 / 固定比例预设 16:9、4:3、1:1）、圆角、描边；蒙版、滤镜列入后期。
- **文本**：富文本编辑（内嵌编辑器），中文字体支持。
- **表格**：单元格内编辑、行列增删、**CSV 粘贴导入**、样式（表头/边框/斑马纹/对齐）、列宽拖拽。
- **形状**：矩形 / 圆角矩形 / 椭圆 / 线条 / 箭头 / 分割线。
- **贴纸**：从素材包拖入画布。
- **背景**：纯色 / 渐变 / 图片（页面级）。

### 5.4 素材库

- 面板：缩略图网格、批量导入（多选文件 / 拖拽）、重命名、删除（删除前检查引用）。
- 性能：原图按需加载，画布与面板使用缩略图缓存。

### 5.5 模板系统

- **内置六类模板**（第一版全做）：
  1. 装备推荐（卡片网格：装备图 + 名称 + 获取途径 + 推荐度）
  2. 属性 / 数值对比（表格为主：属性面板、武器对比）
  3. 剧情流程（时间线 / 步骤条：章节 → 关键节点 → 分支选项）
  4. 武器 / 角色评测（大图 + 评分条 + 优缺点列表）
  5. 地图 / 点位（背景图 + 标注点）
  6. 通用封面（标题 + 副标题 + 配图 + 作者署名位）
- 新建攻略时选择模板 → 生成初始页面，之后自由编辑。
- "保存为模板"：把做好的攻略 / 页面存为新模板，按类型分类。
- 模板导入 / 导出（`.json`），可分享给他人。
- 后期能力：模板占位符 / 变量（标记可替换区域）。

### 5.6 美化包

- **主题包**：配色（主色/辅色/背景/文字）、字体（标题/正文）、组件默认样式；应用粒度为项目级。
- **素材包**：标题装饰线、角标、推荐度星标、箭头、分割线、卡片边框等装饰素材，拖入画布即用；支持导入 / 导出分享。
- 与模板**解耦**：模板管布局，美化包管外观，自由组合。
- 第一版内置：画布配色仅「浅色页面」一套 + 一套基础素材包。
- 界面深浅色由独立的**界面外观**设置负责（深色 / 浅色 / 跟随系统，玻璃拟态材质），
  与画布配色解耦——画布配色管页面内的主色/辅色，界面外观管窗口与控件外观。

### 5.7 导出

**图文攻略（页面型）**

- 形态：单页 PNG / 当前攻略全部页（批量）/ 长图（页面纵向拼接，无缝或带分隔线选项）。
- 分辨率倍率：1x / 2x / 3x（**默认 2x**——小黑盒会压缩图片，宁大勿小）。
- 剪贴板复制：复制当前页 / 全部页到剪贴板，直接粘贴进小黑盒编辑器（不做一键发布，小黑盒无公开 API，浏览器自动化脆弱易失效）。
- 尺寸预设：小黑盒（规格待实测后填入）+ 自定义（保存常用尺寸）。
- 命名规则：`攻略名_01.png`，导出到指定文件夹，带导出进度。

**文章攻略（文章型）**

| 格式 | 产物 | 署名 |
|---|---|---|
| Markdown | `文章名.md`（原样，保留 `![[W:P]]`）+ `文章名_compatible.md`（引用替换为图片，外部阅读器可看）+ `images/`（页面渲染图 + 素材副本） | 无 |
| PNG 长图 | `文章名.png`，宽 1080，高度自适应；字号按宽度比例缩放 | 水印（位置可选四角） |
| PDF | `文章名.pdf`，A4 自动分页 | 文末署名行 |

署名由全局设置"作者署名" + 导出对话框"添加作者署名"复选框控制（图文攻略的署名同样逻辑）。
水印样式（位置 / 字体 / 字号 / 加粗 / 颜色 / 不透明度）由导出对话框的「署名设置…」按钮打开设置，
经 QSettings 持久化（`authorMark/*` 键），并随 `PluginContext` 传给导出 Provider——
因此**不改 `IExportProvider` 接口签名**，第三方插件保持向后兼容。

导出完成后统一显示"导出完成"对话框，提供"打开目录"按钮。

### 5.8 文章攻略（Markdown）

- **编辑**：分栏编辑器（左 Markdown 源码 / 右实时预览，300ms 防抖）。
- **工具栏**：加粗 / 斜体 / 标题 / 列表 / 链接 / 图片 / 页面引用。
- **页面引用**：`![[W:P]]` 引用项目内图文攻略页面，预览中渲染为页面图片；
  工具栏提供图形化页面选择器，无需手输索引。
- **图片**：从本地选图自动复制进项目 `assets/` 并插入相对路径引用。
- **导入**：从 `.md` 文件导入，本地图片自动复制并改写路径。
- **导出**：见 5.7 节。
- **主题联动**：预览与导出（PNG / PDF）的文字颜色跟随当前主题，深色主题下自动使用浅色文字。

### 5.9 全局设置

- 作者署名（如小黑盒 ID）：全局设置项，导出时可选择应用。
- 署名水印样式：位置（左上 / 右上 / 左下 / 右下）、字体族、字号、加粗、颜色、不透明度；
  入口在导出对话框「署名设置…」，与作者署名一起持久化在 QSettings。
- 默认画布尺寸、默认主题、默认字体。
- 自动保存间隔、最近项目数量。
- 界面语言（中文默认）、界面深浅色主题。

## 6. 技术架构

- **技术栈**：Qt 6（Widgets + PrintSupport 模块）+ CMake + C++20。
- **画布**：`QGraphicsScene/View` + 自定义 `QGraphicsItem`（各组件）。
- **导出渲染**：`QPainter` 离屏渲染同一场景，所见即所得，支持倍率输出 PNG。
- **富文本**：`QTextDocument`。
- **文章渲染**：`QTextDocument::setMarkdown()` 渲染 CommonMark + GFM；
  `![[W:P]]` 页面引用替换为图片语法后注册 resource；PDF 用 `QPrinter(PdfFormat)`。
- **序列化**：`QJsonDocument`。

### 6.1 模块分层

```
src/
  app/        # 入口、主窗口、应用装配
  core/       # 数据模型、序列化（project.json）
  editor/     # 画布场景、组件 item、命令（撤销重做）
  project/    # 项目管理、素材库、自动保存
  template/   # 模板解析、模板库
  theme/      # 主题包、素材包
  export/     # 导出、长图拼接、剪贴板
  settings/   # 全局设置
tests/        # 镜像 src/，见第 8 节
docs/         # 文档（本文件）
```

### 文章攻略（M7）实现记录

- **文章归属**：设计初稿把文章与图文攻略定为平级（`Project::vecArticles`），实施中修正为
  **攻略内嵌**（`Walkthrough::vecArticles`）——一个攻略下可同时含页面与文章。
  旧格式（project 级 articles）在反序列化时自动迁移，保证向后兼容。
- **页面引用**：`![[W:P]]` 为项目自定义语法（标准 Markdown 不支持）。
  渲染时替换为 `![](bwm://page/W/P)` 并注册 `QImage` resource；
  导出 `.md` 时保留原文，另出兼容版把引用替换为标准图片语法。
- **图片 resource 注册顺序**：必须在 `setMarkdown()` 之后注册，否则会被重建的 document 清除。
- **图片遍历**：需用 `QTextBlock::iterator` 遍历 fragment 取 `QTextImageFormat`，
  `QTextCursor` 逐字符移动取不到。
- **字号**：`QTextDocument` 默认约 12pt，在 1080px 宽长图上过小；
  改为按宽度比例缩放（`正文 = 宽度 × 44 / 1080`）。
- **文字颜色**：`setMarkdown` 默认渲染黑字，深色主题下不可见；
  改为跟随主题文字色（默认样式表 + 遍历 fragment 兜底）。
- **新增依赖**：`Qt6::PrintSupport`（PDF 导出），`windeployqt` 会自动部署 `Qt6PrintSupport.dll`。
- **测试注意**：含文本渲染的测试用 `QTEST_MAIN`；
  导出完成对话框在 `pParent == nullptr` 时静默，避免模态框阻塞自动化测试。

### 页面背景图（从图片新建页面）实现记录

- **背景图字段**：`Page::strBackgroundImage` 存**项目内相对路径**（如 `assets/xxx.png`），
  而非图片组件所用的绝对路径——项目文件夹整体移动/拷贝后背景图仍然有效。
  渲染时由调用方传入项目目录，经 `AssetStore::resolvePath()` 解析为绝对路径。
- **绘制算法**：`core/PageBackground` 提供「等比覆盖、超出裁剪」（cover），
  画布 `CanvasScene` 与导出 `ExportRenderer` 共用同一实现，保证编辑器所见即导出所得；
  页面与图片比例不符时居中裁剪，既不留白也不变形。
- **入口**：项目树攻略节点右键「从图片新建页面…」（菜单栏「攻略」菜单有同款入口）——
  页面尺寸取图片原始像素尺寸，图片复制进 `assets/` 后作为整页底图；
  页面节点右键另有「设置背景图…」（图片与页面比例不符时询问是否同步调整页面尺寸）与「清除背景图」。
- **素材路径复用**：外部图片复制进 `assets/` 的逻辑统一收敛到 `project/AssetStore`，
  图片组件 Provider、素材面板导入、页面背景图三处共用，避免各写一份。
- **连带改动**：`ExportRenderer::renderPage` / `renderLongImage` 与
  `ArticleRenderer::renderPageRef` 增加**项目目录**参数（默认空，保持向后兼容），
  使导出 PNG、长图、文章内 `![[W:P]]` 引用、Markdown 预览缩略图、复制页面到剪贴板都能带上背景图；
  素材面板删除素材时新增「页面背景图引用」检查，避免删掉正在使用的底图。
- **序列化上限**：`ProjectSerializer` / `TemplateSerializer` 的单边 16384px 防线不变，
  导入超限图片时先等比缩小再作为页面尺寸，避免读回时被静默回退成默认尺寸。
- **测试**：`test_project_serialization` 与 `test_template` 增加背景图字段往返用例
  （含旧文件缺字段的向后兼容），`test_page_background` 覆盖覆盖式裁剪计算与实际绘制，
  `test_canvas_scene` 把画布场景渲染成图片后取像素，锁定层序。
- **实施中发现并修复的问题（层序写反导致画布全白）**：画布上页面背景图图元与
  「主题背景色矩形」的 Z 值最初写反（图片 -2、不透明矩形 -1），矩形把整张背景图盖住，
  表现为「从图片新建页面 / 设置背景图之后画布仍是一片白」；而导出渲染是先填背景色再画背景图，
  所以文章内 `![[W:P]]` 引用与导出 PNG 都正常——这个差异正是定位该问题的关键线索。
  现固定层序为：背景色矩形 -2 < 背景图 -1 < 组件（`zOrder` 自 1 起）。
  回归保护：`tests/editor/test_canvas_scene.cpp`（把层序改回错误值该测试即失败，已实测验证）。

### 卡片边框形状扩展实现记录

- **形状合并到一个插入项**：矩形（圆角）/ 正方形 / 圆形 / 椭圆四种形状**不拆分**成多个
  「插入」菜单项，仍是「插入/装饰/卡片边框」一项；形状作为插入时对话框的选项，
  插入后双击组件或右键「编辑卡片边框…」可再次修改。
- **几何约定**：正方形/圆形取组件矩形的**内接正方形**（居中）——因此组件较宽时两侧留空；
  矩形/椭圆填满组件矩形。用户确认形状为正方形/圆形后，组件尺寸会**归一为 1:1**
  （以短边为准，位置不变），避免选择手柄比图形大一圈；缩放手柄逻辑未改动，之后自由拉伸仍按内接绘制。
- **双击线与旧版一致**：矩形形状下外框线宽 3/圆角 8、内框线宽 1/圆角 5，与改造前像素一致，
  不影响已有项目观感；形状过小时（内框不足 2px）只画外框，避免两圈线重叠。
- **序列化**：仅卡片边框写 `borderShape` 字段（其余贴纸不写，保持 JSON 精简），
  旧文件缺该字段按矩形处理，视觉与旧版本完全一致。
- **设置对话框**：`src/plugin/builtin/CardBorderDialog.*`（形状下拉 + 颜色 + 预览）。
  放在 plugin/builtin 层，是因为 **core 层的插入流程**（`StickerComponentProvider::showInputDialog`）
  与 **app 层的组件编辑**（`ComponentItem::editCardBorder`）都要调用它。
  预览直接复用 `ComponentPainter` 渲染到图片，保证与画布、导出所见即所得。
- **测试**：`tests/core/test_card_border.cpp` 覆盖四种形状的序列化往返、
  「形状字段只对卡片边框写入」，以及把组件渲染成图片后的像素断言
  （正方形两侧无线条、圆形/椭圆四角无线条）。

### 卡片边框图片裁剪实现记录

- **需求**：卡片边框框起来的区域内展示一张图片——**框内显示、框外隐藏**。
- **数据**：`StickerData` 增加 `strImagePath`（项目内**相对路径**，空 = 无图片）与
  `dImageOffsetX` / `dImageOffsetY`（取景位置 0~1，0.5 = 居中）。
  旧文件缺这些字段时按「无图片 + 居中取景」处理；仅在卡片边框且有图片时写入 JSON。
- **绘制**：`ComponentPainter` 的卡片边框分支先按形状生成裁剪路径（`setClipPath`），
  图片以「等比覆盖」铺满外框后绘制，**再描边框线**（线在图片之上不被盖住）。
  圆形/椭圆的四角自然被裁掉；正方形/圆形时图片被限制在内接正方形内。
- **取景算法统一**：新增 `core/ImageFit`（等比覆盖 + 取景偏移），页面背景图
  （`core/PageBackground`）改为转发调用它——两者规则完全一致、单一实现来源。
- **项目目录传递**：`ComponentPainter::paint` 增加项目目录参数（默认空，向后兼容）；
  `ComponentItem` 增加 `setProjectDirectory()`（由 `CanvasScene` 注入并同步已有图元），
  导出链路沿用 `ExportRenderer` 已有的项目目录参数。图片缓存改为**按路径变化失效**，
  因此在编辑器里换图后立即生效（原先只在缓存为空时加载）。
- **交互**：`CardBorderDialog` 增加「框内图片」（选择 / 清除）与「水平位置 / 垂直位置」滑块，
  预览实时反映取景；无图片时滑块自动禁用。选图经 `AssetStore` 复制进 `assets/` 并存相对路径，
  清除只清引用、素材文件保留在素材库。
- **素材保护**：素材面板删除素材时新增「卡片边框图片引用」检查。
- **测试**：新增 `test_image_fit`（覆盖取景与偏移、越界夹紧、实际绘制取到图片的不同部分）；
  `test_card_border` 增加「圆形四角无图片像素」「偏移改变可见部分」「正方形时图片限制在内接正方形」用例。
- **实施中发现并修复的问题（构造期回调顺序）**：对话框构造时先给取景滑块赋初值、后创建预览控件，
  `setValue` 触发的 `valueChanged` 回调会访问**尚未创建**的预览控件，表现为
  「点击插入/卡片边框立即闪退」；同一回调还会从**两个**滑块读值写回数据，
  给其中一个赋初值时另一个仍是 0，会把该方向的取景位置错误地改成居中（Y 永远居中）。
  现改为：所有控件创建完成后再赋初值，并用 `QSignalBlocker` 屏蔽这两个 `setValue`；
  刷新函数（`updatePreview` / `updateImageRow`）加空指针防御。
  **回归保护**：新增 `tests/plugin/builtin/test_card_border_dialog.cpp`——
  直接构造对话框（默认、带图 + 非默认取景、四种形状），构造期的空指针或数据被回调改写都会失败；
  此前只测绘制、不构造对话框，因而漏掉了这类问题。
- **实施中发现并修复的问题（换图后画布仍显示旧图）**：`ComponentItem` 的图片缓存按路径失效，
  但刷新只放在 `setComponent()` 里；卡片边框的编辑流程 `editCardBorder()` 是直接改 `m_component`，
  没有刷新缓存，于是「二次编辑替换图片后，边框内仍显示最初那张图」（导出不受影响，
  导出走无缓存路径，每次重新加载）。
  现收敛出统一的数据变更入口 `ComponentItem::applyComponentData()`（更新数据 → 缓存按路径失效 →
  重绘），编辑流程与 `setComponent()` 都走它，构造函数也统一调用缓存刷新；
  **今后任何改动组件数据（尤其是图片路径）的代码都必须经此入口**。
  回归保护：`test_canvas_scene` 增加「卡片边框换图后画布显示新图」用例（禁用刷新该用例即失败，已实测验证）。

### 「插入 → 文本」接入字体组件实现记录

- **需求**：文本插入时能直接设置字体、字号、颜色等样式，并复用署名设置里封装好的字体组件，
  避免「插入后再双击组件改样式」的绕路操作。
- **对话框**：新增 `plugin/builtin/TextStyleDialog`（文本内容 + 对齐方式 + `ui/FontSelectWidget`）。
  放在 plugin/builtin/ 层是因为插入流程（`TextComponentProvider::showInputDialog`）与
  编辑流程（`ComponentItem::editTextContent`）都要调用它；**两处统一复用**后，
  `ComponentItem` 里原先手写的那份内联对话框已删除，不再存在两套不一致的 UI。
- **文本不透明度**：`TextData` 增加 `nOpacityPercent`（默认 100），
  `ComponentSerializer` 读写 `opacity`（旧项目文件缺该字段回退 100，向后兼容），
  `ComponentPainter` 绘制文本时把不透明度合成到颜色 alpha；`operator==` 同步参与比较。
  颜色仍只存 `#RRGGBB`（`colorToString` 不保留 alpha），透明度单列存储，与署名水印的做法一致。
- **默认字体来源收敛**：新增 `textDefaultFontFamily()`（原先硬编码在 `ComponentPainter`），
  绘制与设置界面共用同一默认字体，避免两处默认值漂移。
- **对齐值的兼容处理（实施中发现的问题）**：`Qt::AlignLeft`(1) 与 `AlignLeft|AlignVCenter`(129)
  的 `drawText` 渲染结果**并不相同**（垂直位置不同）。旧「编辑文本」对话框把「左对齐」写成 129，
  而 `TextData` 默认是 1：若新对话框直接沿用 129，插入的新文本会垂直居中，与旧版本排版不一致。
  现做法：下拉框的「左对齐」用历史默认值 1，且**水平对齐未变时保留原值写回**
  （1 / 129 两种历史取值都不会无故跳变），只有用户真的改变水平对齐方式时才写入规范值。
- **测试**：新增 `tests/plugin/builtin/test_text_style_dialog.cpp`（默认值 / 数据往返 / 字号与不透明度收敛 /
  对齐原值保留）、`tests/core/test_text_style.cpp`（默认值、相等比较、序列化往返、旧文件缺字段回退、
  不透明度绘制像素断言、字号绘制断言）；`tests/core/test_project_serialization.cpp` 增加文本不透明度往返。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 小黑盒图片规格未核实（单张上限/张数/推荐尺寸） | 导出默认 2x 宁大勿小；尺寸预设可自定义；软件可用后实测上传验证 |
| Qt 学习成本（若未使用过 Qt） | M1 先做画布小原型验证技术路线再全面铺开 |
| 大图性能（4K 游戏截图） | 缩略图缓存、按需加载、原图延迟解码 |
| 范围膨胀 | 严格按里程碑推进，M4 前不碰模板与美化 |
| 长图高度超过 QImage 限制（约 32767px） | 图文与文章长图导出前均检测高度上限（30000px），超限时提示拆分导出 |
| 模板/主题格式变更破坏旧项目 | `formatVersion` + 迁移函数，测试覆盖 |

## 10. 明确不做（本期范围外）

- 一键发布到小黑盒（无公开 API）。
- 云同步 / 多设备（数据格式预留迁移性）。
- 蒙版、滤镜、GIF 导出（后期迭代）。
- 模板占位符 / 变量（后期迭代）。
- 移动端版本。

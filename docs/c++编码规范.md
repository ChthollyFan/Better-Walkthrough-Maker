## 1. 概述
对于高质量的工程，一般会做到：
- 代码简洁精炼，美观，可读性好，高效率，高复用，可移植性好，高内聚，低耦合，没有冗余；不符合这些原则，必须特别说明。
- 规范性，代码有规可循。特殊排版、特殊语法、特殊指令，必须特别说明。

## 2. 文件排版
### 2.1. 包含头文件
a) 系统头文件与用户头文件包含区分开，不交叉。
b) 系统头文件，稳定的目录结构，应采用包含子路径方式。`#include <sub/test.h>`
c) 系统头文件使用尖括号：`#include <xxx.h>`
d) 自定义头文件使用双引号：`#include "xxx.h"`
e) 只引用需要的头文件。
f) 将所有`#include`的文件名视为大小写敏感。能使用前向声明的情况下，优先使用声明。

### 2.2. h和cpp文件
a) 头文件命名为`*.h`，内联文件命名为`*.inl`；C++源文件命名为`*.cpp`。
b) 文件名不要用无意义的名称：例如`XImage.cpp`，项目内命名方式统一。
c) 头文件除特殊情况，必须使用`#ifdef`头保护控制块。
d) 头文件`#endif`末尾增加行尾注释标识保护宏。
e) 头文件内容顺序：全局函数 → 宏定义 → 全局变量 → 全局常量 → 类型定义 → 类定义 → 内联实现。
f) cpp文件内容顺序：头文件包含指令 → 宏定义 → 全局变量 → 函数定义。

### 2.3. 文件结构
a) 文件必须包含文件头注释与业务代码内容。
b) 函数体、类体之间原则上空一行，特殊场景可不留空行。

### 2.4. 空行
文件头、头文件保护块、`#include`段、宏定义段、class定义段、全局常量段、全局变量段、函数与函数之间，均使用一个空行分隔。

## 3. 注释方面
### 3.1. 文件头注释
模板需包含：作者 zhangweimu、文件名称、文件功能说明、生成日期(可选)。

### 3.2. 函数注释
a) 关键函数必须添加注释，说明函数用途，统一使用注释模板。
b) 复杂参数需要说明参数含义、内存归属、释放责任等。
c) 除非特殊场景，注释统一写在代码前，不写在行尾。
d) 所有`#else`/`#endif`末尾添加行尾注释，标注对应宏。
e) 关键代码必须加注释：赋值、函数调用、复杂表达式、分支判断等。
f) 未完成/待优化代码添加：`// TODO xxx`。
g) 调试临时代码添加：`// DEBUG xxx`。
h) 需要重点关注的逻辑添加：`// NOTE xxx`。
i) 超长循环代码块结尾（for/while/do）可添加行尾注释标识代码块结束：`// end for`。

### 3.3 日志规范
日志开头需要包含类名+方法名, 例如 [class::method]

## 4. 命名方面
### 4.1. 原则
a) **同一性**：子模块/派生类命名风格必须与基类、整体模块保持统一。
b) **标识符组成**：使用英文单词组合，表意清晰可读；禁止拼音命名。
c) **最小长度+最大信息量**：表意清晰前提下尽量缩短变量名。
d) **避免近似名称**：禁止仅靠大小写区分标识符，如`i`与`I`、`function`与`Function`。
e) **不同作用域禁止重名**：局部变量与全局变量禁止同名，避免阅读混淆。
f) **互斥语义反义词**：成对接口使用反义词命名，如`minValue`/`maxValue`、`getName()`/`setName()`。
g) **尽量不用数字编号**：避免`Value1`/`Value2`，仅逻辑强制有序时使用数字。

### 4.2. 函数
a) 类成员函数采用小驼峰`handleXXX`，禁止`HandleXXX`；除非C标准库/STL，不使用下划线命名`handle_color`，避免与系统API混淆。
b) 函数参数数量尽量不超过6个，参数过多优先封装结构体传入。
c) 参数过多排版优化：语义相近参数同行，或每个参数单独一行竖向对齐。

### 4.3. 变量
a) 变量采用小驼峰命名；基础类型统一增加类型前缀，多类型叠加时取最核心类型前缀：
    | 基础类型 | 前缀 | 示例 |
    | ---- | ---- | ---- |
    | int | n | nValue |
    | bool | b | bEnable |
    | long | l | lCount |
    | float | f | fRatio |
    | double | d | dScore |
    | string | str | strName |
    | list | lst | lstData |
    | vector | vec | vecList |
    | map | map | mapInfo |
    | enum | e | eState |
    | 指针 | p | pObj |
    | 引用 | r | rData |
    | 数组 | a | aBuffer |
    > 示例：int指针 → p；指针数组 → a；数组指针 → p。

b) 变量作用域前缀（前缀+下划线）：
    | 作用域 | 前缀 | 示例 |
    | ---- | ---- | ---- |
    | 类成员变量 | m_ | m_nValue |
    | 全局变量 | g_ | g_lTotal |
    | 静态变量(全局/成员) | s_ | s_pCache |

### 4.4. 类型名
a) 类、结构体使用大驼峰：`MyClass`、`MyStruct`。
b) 类/结构体使用名词命名。
c) 枚举类型：`E_`开头、全大写、下划线分隔；枚举值以枚举类型名作为前缀。
    示例：枚举类型`E_TYPE_STUDENT_INFO`，枚举值`E_TYPE_STUDENT_INFO_NUMBER`。
d) 宏定义：`DEF_`开头、全大写、下划线分隔，示例：`DEF_TYPE_ID`。

### 4.5. 风格兼容性
移植/开源第三方代码可保留原有编码风格，不受本C++命名规范约束。

## 5. 代码风格
### 5.1. Tab和空格
a) 缩进统一使用4个空格，禁止Tab制表符。
b) 代码行末尾禁止多余空格。
c) `::` / `->` / `.` 前后不加空格。
d) `,` / `;` 前面不加空格，后面加空格。

### 5.2. 类型定义和{
a) class/struct/enum/union：大括号另起一行。
b) 函数`{`单独起一行，缩进与函数声明对齐。
c) 函数体内禁止连续两个空行（特殊场景除外）。
d) 函数内不允许宏定义，仅该函数专属宏除外。
e) 函数内逻辑紧密语句不加分隔空行，逻辑块之间空一行分隔。

### 5.3. 代码块
a) `if`/`for`/`while`/`do`/`try`/`catch`独占一行，执行语句不跟在同行；无论单行多行，必须包裹`{}`。
b) 关键字与括号紧贴：`if(xxx)`，不写 `if (xxx)`。

### 5.4. 代码行
a) 一行只做一件事：单行仅定义一个变量 / 仅一条语句。
b) 多变量竖向对齐，提升可读性。
c) 单行字符限制80个，保证单屏完整展示。

### 5.5. 宏
a) 宏定义末尾不加分号。
b) 优先使用内联函数/const常量，尽量避免宏，方便调试。

### 5.6. goto
禁止使用`goto`。

## 6. 类型
a) 指针`*`、引用`&`紧贴变量名：`int* pVal`、`std::string& rStr`。
b) 无业务需求尽量避免浮点数。
c) 使用`typedef`简化复杂复合类型。
d) 禁止匿名枚举/结构体，必须命名。
    错误示例：`enum { IDLE, ACTIVE };`
    规范示例：`enum TState { EIdle, EActive };`
e) 少用union，必须使用时仅存放基础简单类型。
f) 使用enum替代一组相关常量。
g) 禁止直接使用魔鬼数字，用常量/枚举替代。
h) 优先引用，次选指针。
i) 变量定义时立即初始化，遵循就近定义原则，使用前再定义。
j) 优先多态替代强制类型转换；必须转换时优先`dynamic_cast`。

## 7. 表达式
a) 禁止在判断表达式内部赋值。
b) 浮点数禁止直接`==`/`!=`判等，使用误差区间对比。
c) 枚举变量禁止运算后赋值。
d) 循环内禁止修改循环计数器。
e) 空指针判断：`if(p)`
f) 非空指针判断：`if(!p)`

## 8. 函数
### 8.1. 引用
a) 函数返回引用：必须保证返回对象生命周期有效。
b) 函数入参引用：调用方必须传入有效存在的对象。

### 8.2. 返回值
a) 除void、构造、析构函数外，所有函数必须显式return，每个分支都要有返回。
b) 返回指针/引用时，注释说明对象生命周期。

### 8.3. 内联函数
a) 内联函数实现放在类体外`.inl`或`.cpp`，不写在类声明内。
b) 仅简单短逻辑函数使用inline，复杂业务禁止内联。
c) 虚函数禁止inline。

### 8.4. 函数参数
a) 仅读取不修改：`const T&`常量引用。
b) 需要修改/输出：`T&`非常量引用。
c) 基础简单类型：值传递。
d) 复杂结构体/对象：引用或指针传递。
e) 输入参数放前，输出参数放后（默认参数除外）。
f) 通用业务库尽量不使用默认参数。

## 9. 类
### 9.1. 整体结构
a) 访问权限顺序：`public` → `protected` → `private`，无对应模块直接省略。
b) 每一块内部顺序：
    1. 嵌套类型（typedef / enum / struct / class）
    2. 常量定义
    3. 构造函数
    4. 析构函数
    5. 成员函数（含静态函数）
    6. 成员变量（含静态变量）
c) cpp文件函数实现顺序与头文件声明顺序保持一致。

### 9.2. 构造函数
a) 初始化列表成员顺序与类内成员定义顺序保持一致。
b) 初始化列表每个成员单独一行。
c) 禁止使用同类另一个成员初始化当前成员。
d) 构造函数初始化全部成员，指针必须置空。
e) 构造、析构函数内部禁止抛出异常。

### 9.3. 纯虚函数
抽象接口类统一使用纯虚函数定义接口。

### 9.4. 构造和析构函数
a) 允许继承的基类，析构函数定义为`virtual`。
b) 禁止继承的类，析构函数不使用virtual。
c) 禁止拷贝的类，将拷贝构造、赋值运算符私有。
d) 自定义构造函数的类，必须配套析构函数。

### 9.5. 成员变量
a) 尽量不使用`mutable`（互斥锁mutex除外）、`volatile`。
b) 禁止公有成员变量，统一提供get/set接口。

### 9.6. 成员函数
a) 类接口精简完备，最小对外暴露。
b) 只读接口优先使用`const`常成员函数。
c) 禁止重定义父类非虚函数。
d) 重写父类虚函数添加`override`关键字，编译器校验。
e) 不允许子类重写的虚函数添加`final`关键字（C++11）。

### 9.7. 继承
a) 继承严格遵循IS-A；组合HAS-A不用继承。
b) 虚函数禁止使用默认参数。
c) 虚函数功能单一，不设计大而全接口。
d) 尽量避免基类强转派生类。

## 10. 错误处理
a) 内存释放后指针置空，杜绝野指针。
b) 使用指针前判空，处理空指针分支。
c) 数组访问前校验索引合法性，处理越界。
d) 卫式写法：优先处理异常错误分支，再处理正常主逻辑。

## 11. 性能
a) 头文件优先前向声明替代`#include`，减少编译依赖。
    ```cpp
    class M;
    ```
b) 循环外提前计算循环不变表达式，避免重复计算。
c) 禁止循环内频繁创建销毁对象。
d) 避免高开销对象拷贝。
e) 减少大型临时对象生成。
f) 谨慎使用大尺寸对象数组。
g) 优先使用STL标准算法，不重复造轮子。

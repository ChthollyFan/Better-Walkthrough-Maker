# 开发环境与构建

## 1. 依赖

| 依赖 | 版本 / 说明 |
| --- | --- |
| CMake | ≥ 3.21 |
| 生成器 | Ninja |
| 编译器 | MinGW-w64 g++ 14.2（本地）/ 13.1（CI，随 Qt 6.8.3 配套） |
| Qt | 6（MinGW 版）。本地开发用 6.11.2；CI 用 6.8.3 LTS |
| C++ 标准 | C++20（`CMAKE_CXX_STANDARD 20` + `CXX_STANDARD_REQUIRED ON`） |
| Qt 模块 | `Qt6::Widgets`、`Qt6::PrintSupport`（主程序）；`Qt6::Test`（测试） |
| 系统库 | Windows 下额外链接 `dwmapi`（亚克力窗口效果） |

本地 Qt 路径示例：`C:/Users/ThinkPad/Qt/6.11.2/mingw_64`（aqtinstall 的 7z 包手动解压安装）。
若机器上同时存在 MSVC 版 Qt，环境变量 `Qt6_DIR` 会干扰 CMake 探测，**配置时必须显式覆盖**。

## 2. 配置与编译

```powershell
# 配置（显式指定 MinGW 版 Qt，覆盖环境变量 Qt6_DIR 的干扰）
cmake -S . -B build -G Ninja `
  "-DCMAKE_PREFIX_PATH=C:/Users/ThinkPad/Qt/6.11.2/mingw_64" `
  "-DQt6_DIR=C:/Users/ThinkPad/Qt/6.11.2/mingw_64/lib/cmake/Qt6" `
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++

# 编译
cmake --build build
```

使用 `CMakePresets.json` 可简化为：

```powershell
cmake --preset windows-mingw-release
cmake --build --preset release
ctest --preset release
```

预设：

| 预设 | 用途 |
| --- | --- |
| `windows-mingw-release` / `release` | 默认开发构建，输出到 `build/` |
| `windows-mingw-debug` / `debug` | 调试构建，输出到 `build-debug/`；当前 Qt 只装了 Release 库，链接 Qt 可能失败，主要用于代码浏览与编译检查 |

## 3. 编译产物

| 产物 | 路径 |
| --- | --- |
| 主程序 | `build/src/bwm.exe` |
| 核心静态库 | `build/src/libbwm_core.a` |
| 测试程序 | `build/tests/<test_name>.exe` |

`bwm_core` 是静态库，主程序与全部测试共用；`bwm` 目标只包含 `src/app/`、`src/editor/`
与资源文件。

## 4. 运行主程序

首次编译（或清空 `build/`）后需要先部署 Qt 运行时 DLL 到 exe 同目录：

```powershell
C:\Users\ThinkPad\Qt\6.11.2\mingw_64\bin\windeployqt.exe --release --compiler-runtime build\src\bwm.exe
build\src\bwm.exe
```

也可以只把 Qt 的 `bin` 目录加进 `PATH` 后运行，但双击 exe 时会找不到 DLL，
推荐用 `windeployqt` 做自包含部署。

> 清空 `build/` 重新配置后，`windeployqt` 复制过去的 DLL 会一起丢失，需要重新执行一次。

## 5. 运行测试

```powershell
$env:PATH = "C:/Users/ThinkPad/Qt/6.11.2/mingw_64/bin;" + $env:PATH
ctest --test-dir build --output-on-failure
```

当前共 **16 个测试程序**：

| 测试 | 覆盖内容 |
| --- | --- |
| `test_project_serialization` | 数据模型与 `project.json` 序列化、缺字段、损坏文件、版本检查、旧格式兼容 |
| `test_project_manager` | 创建 / 保存 / 打开、非法输入、快照恢复、自动保存 |
| `test_export_renderer` | 单页尺寸与像素、长图拼接（含分隔线）、写 PNG、背景图、署名位置与样式 |
| `test_article_export` | `.md` 导入与图片复制、文档构造、三种导出格式、深色主题文字可见性 |
| `test_article` | 文章序列化往返、页面引用标记、旧格式迁移、容错解析 |
| `test_template` | 模板往返、文件读写、内置六类模板结构、错误输入 |
| `test_card_border` | 四种边框形状的序列化与绘制、框内图片裁剪与取景 |
| `test_text_style` | 文本样式默认值、序列化往返、缺字段回退、不透明度与字号绘制 |
| `test_author_mark_style` | 署名样式默认值、位置字符串往返、区间收敛 |
| `test_image_fit` | 等比覆盖 + 取景偏移算法与绘制 |
| `test_page_background` | 页面背景图覆盖式裁剪计算与绘制 |
| `test_font_select_widget` | 字体控件读写往返、信号、行显隐 |
| `test_card_border_dialog` | 对话框构造期回归（默认 / 带图 / 四种形状） |
| `test_text_style_dialog` | 文本样式对话框数据往返与对齐原值保留 |
| `test_canvas_scene` | 把画布场景渲染成图片取像素，锁定层序（背景色 < 背景图 < 组件） |
| `test_author_mark_dialog` | 署名设置对话框样式往返 |

测试约定（与 `AGENTS.md` 一致）：

- 测试放 `tests/`，目录结构镜像 `src/`，命名 `test_<单元>_<行为>`
- 涉及文本渲染的测试需用 `QTEST_MAIN`（字体数据库需要 `QGuiApplication`），
  不能用 `QTEST_GUILESS_MAIN`
- 画布与部分 `src/app/` 代码属于主程序目标，测试通过**额外编译对应 `.cpp`** 来覆盖
  （见 `test_canvas_scene`、`test_author_mark_dialog`）
- 暂不设覆盖率阈值，重点覆盖公开行为与错误路径

## 7. 环境提示

- 本机 CMake / 编译命令在某些沙箱环境下需要**完整权限**：工具链会启动 `g++` 并捕获输出，
  受限的管道可能挂起。
- 修改代码后建议按 `AGENTS.md` 的约定重新编译并生成单文件 exe，交给实际使用者验证。

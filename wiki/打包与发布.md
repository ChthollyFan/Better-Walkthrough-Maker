# 打包与发布

> **发布产物只有一个**：单文件 `BWM.exe`（免安装、无需 Qt DLL）。
> 完整的发布流程（含 tag、CHANGELOG、回滚与检查清单）见仓库根目录
> [`AGENTS.md`](../AGENTS.md) 的「Tag 发布流程」；本页只讲脚本与自动化。

## 1. 本地打包

### 第一步：文件夹版（为单文件打包做前置准备）

```powershell
pwsh -File package.ps1
```

脚本做的事：

1. 检查 `build/src/bwm.exe` 是否存在（不存在则提示先执行 `cmake --build build`）
2. 清空并重建 `release/`，把 exe 复制进去
3. 执行 `windeployqt --release --no-translations release\bwm.exe` 部署 Qt 运行时
4. 默认**删除 `release/opengl32sw.dll`**（软件光栅器，目标机需有显卡驱动）；
   `-KeepSwrast 1` 可保留（体积约回到 60MB）
5. 打包出 `Better-Walkthrough-Maker.zip`

可用参数：`-QtDir <Qt 路径>`（默认取本机 MinGW 版 Qt，再回退环境变量 `QT6_DIR`）、`-KeepSwrast`。

产物：`release/`（exe + Qt DLL + 平台插件）、`Better-Walkthrough-Maker.zip`。

### 第二步：单文件 exe（发布用）

```powershell
pwsh -File package_single.ps1
```

- **前置条件**：`release/bwm.exe` 已存在（即先跑过 `package.ps1`），
  且打包工具可用（优先仓库内 `tools/enigmavbconsole.exe`）
- 脚本递归生成 Enigma Virtual Box 的 `.evb` 项目文件到 `build/bwm.evb`，
  把 `release/` 下的所有文件虚拟进 exe（主 exe 作为启动项，不放进虚拟文件系统），
  再调用命令行工具产出根目录的 `BWM.exe`
- 可用参数：`-EnigmaDir <路径>`、`-OutputName <名字>`

产物：仓库根目录 `BWM.exe`。

> ⚠️ 打包顺序不可颠倒；打包前请**关闭正在运行的 `BWM.exe` / `bwm.exe`**，
> 否则覆盖产物会因文件占用而失败。

## 2. 版本号

版本号**只有一个来源**：顶层 `CMakeLists.txt` 的 `project(BetterWalkthroughMaker VERSION x.y.z)`。

```
CMakeLists.txt (VERSION)
   └─ src/CMakeLists.txt: target_compile_definitions(bwm PRIVATE BWM_VERSION="...")
        └─ main.cpp: QCoreApplication::setApplicationVersion(BWM_VERSION)
             └─ 「关于」对话框 / 窗口标题显示
```

- `src/app/main.cpp` 中的同值只是**脱离 CMake 编译时的回退**
- tag 名必须与版本号一致：`VERSION 0.4.0` ↔ `git tag v0.4.0`
- 不要复用已发布过的版本号；dev 分支内容领先上一个 tag 时必须递增版本号
- 升版时同步更新 `CHANGELOG.md`

## 3. 自动发布（GitHub Actions）

工作流：`.github/workflows/release.yml`

- 触发：推送 `v*` 标签，或手动 `workflow_dispatch`
- 并发控制：同一时刻只保留一个运行（`cancel-in-progress`）
- 权限：`contents: write`（创建 Release）

Job 步骤（`windows-latest`）：

| 步骤 | 内容 |
| --- | --- |
| Checkout | `actions/checkout@v5` |
| 安装 Qt | `jurplel/install-qt-action@v4`，Qt **6.8.3** + `win64_mingw` + `tools_mingw1310` |
| 定位工具链 | 优先用 `Qt6_DIR`，否则递归查找 `qmake6.exe` 反推前缀；把 `g++` 加入 `PATH` |
| 配置 / 编译 / 测试 | `cmake ... -G Ninja` → `cmake --build build` → `ctest --output-on-failure` |
| 部署运行时 + 打包 | `windeployqt` → `package.ps1` → `package_single.ps1` → 校验 `BWM.exe` |
| 抽取 Release 说明 | 仅 tag 时：按 `v` 去掉前缀得到版本号，从 `CHANGELOG.md` 抽取 `## [x.y.z]` 段落到 `release_notes.md` |
| 创建 Release | 仅 tag 时：`softprops/action-gh-release@v2`，上传 `BWM.exe`，正文用 `release_notes.md` |
| 上传产物 | 仅手动触发时：`actions/upload-artifact@v4` |

> CI 用的是 Qt **6.8.3 LTS** + MinGW 13.1（aqt 3.3.0 不识别 Qt 6.11+ 的新目录结构），
> 与本地开发的 Qt 6.11.2 不同，但构建产物一致。

## 4. CHANGELOG 与 Release 说明

- `CHANGELOG.md` 格式参考 Keep a Changelog，分类为 Added / Fixed / Changed 等
- 打 tag 前把 `## [未发布]` 改写为 `## [x.y.z] - YYYY-MM-DD`
- CI 按 tag 版本号抽取对应段落作为 Release 正文；**抽不到时只告警，不会中断发布**，
  因此发布后要到 Release 页面核对说明是否完整
- 要求「CHANGELOG 段落 = tag 正文 = Release 页面说明」三者一致

## 5. 发布前检查清单（摘要）

- [ ] 本地全部测试通过（`ctest --test-dir build --output-on-failure`）
- [ ] `CHANGELOG.md` 已更新并把「未发布」改成 `## [x.y.z] - 日期`
- [ ] 版本号符合语义化版本，且与 tag 名一致、未复用历史版本号
- [ ] `README.md` / Wiki 文档已同步更新
- [ ] 关闭正在运行的 `BWM.exe` / `bwm.exe`
- [ ] 按 `package.ps1` → `package_single.ps1` 顺序打包
- [ ] 把 `BWM.exe` **复制到空目录**（周围无 Qt DLL）双击验证可独立启动
- [ ] 推送 tag 后核对 Actions 结果与 Release 说明

完整清单与回滚流程见 [`AGENTS.md`](../AGENTS.md)。

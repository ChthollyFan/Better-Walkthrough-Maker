# 项目架构

## 1. 目录分层

```
src/
  app/        应用层：入口、主窗口、面板、对话框、命令
  core/       领域模型、序列化、渲染绘制（project.json）
  editor/     画布场景、画布视图、组件图元
  export/     导出渲染、长图拼接、文章文档构造与导入
  project/    项目管理、素材库（AssetStore）
  settings/   全局设置（QSettings）
  template/   内置模板与模板管理
  theme/      画布配色
  ui/         界面外观（玻璃拟态、亚克力）与可复用控件
  plugin/     插件接口、宿主与内置适配器
tests/        镜像 src/ 的单元测试
docs/         设计文档与编码规范
wiki/         本 Wiki
```

构建目标（`src/CMakeLists.txt`）：

| 目标 | 内容 |
| --- | --- |
| `bwm_core`（STATIC 库） | `core/`、`export/`、`project/`、`settings/`、`template/`、`theme/`、`ui/`、`plugin/`（含 `builtin/`）——主程序与测试共用 |
| `bwm`（WIN32 可执行） | 仅应用层：`app/`、`editor/`、资源文件（`resources.qrc`、`app.rc`） |

`bwm_core` 以 `target_include_directories(... PUBLIC src)` 暴露头文件，
因此包含写法统一为 `#include "core/Component.h"` 这种**带模块目录**的形式。

## 2. 各模块职责

### core（领域模型与序列化）

| 文件 | 职责 |
| --- | --- |
| `Project.*` / `Component.*` / `Article.*` / `Template.*` | 领域模型：项目 → 攻略 →（页面 + 文章）→ 组件 |
| `ProjectSerializer.*` | `project.json` 读写、缺字段回退、旧格式迁移 |
| `ComponentSerializer.*` | 单组件的 JSON 读写（含动画式的一类一对象设计） |
| `ComponentPainter.*` | **编辑器与导出共用的组件绘制实现**，保证所见即所得 |
| `ImageFit.*` / `PageBackground.*` | 等比覆盖 + 取景偏移算法（背景图与卡片边框共用） |
| `AuthorMarkStyle.*` | 署名水印样式（位置 / 字体 / 字号 / 加粗 / 颜色 / 不透明度） |

### editor（画布）

| 文件 | 职责 |
| --- | --- |
| `CanvasScene.*` | 页面数据 ↔ 图元的装载、吸附计算、网格绘制、新建组件 |
| `CanvasView.*` | 缩放（`Ctrl+滚轮`）、框选、右键菜单、背景绘制 |
| `ComponentItem.*` | 单个组件的选中框、8 个缩放手柄、旋转手柄、双击编辑、锁定处理 |

### export（导出）

| 文件 | 职责 |
| --- | --- |
| `ExportRenderer.*` | 离屏渲染单页 / 长图、署名水印绘制、写 PNG |
| `ArticleRenderer.*` | Markdown → `QTextDocument`（含 `![[W:P]]` 资源注册）、页面引用渲染、文件名净化 |
| `ArticleImporter.*` | 从 `.md` 导入文章、复制并改写本地图片路径 |
| `ExportResultHelper.*` | 「导出完成」提示框（父窗口为空时静默，便于测试） |

### 其它

| 模块 | 职责 |
| --- | --- |
| `project/ProjectManager.*` | 新建 / 打开 / 保存、自动保存定时器、快照恢复、最近项目 |
| `project/AssetStore.*` | 素材导入（UUID 命名复制进 `assets/`）、相对 / 绝对路径转换与解析 |
| `settings/Settings.*` | 全部全局设置的静态读写（QSettings） |
| `template/*` | 六类内置模板 + 项目模板的保存 / 导入 / 导出 |
| `theme/Theme.*` | 画布配色（主色 / 辅色 / 背景色 / 文字色） |
| `ui/*` | 界面外观（`GlassStyleProvider`、`AcrylicHelper`、`UiStyleManager`）与 `FontSelectWidget` 复用控件 |
| `plugin/*` | 扩展点接口、`PluginHost` 注册表、内置适配器 |

## 3. 数据流

```
                 ┌───────────────── 编辑 ─────────────────┐
 project.json ←→ ProjectManager ←→ MainWindow ←→ CanvasScene ←→ ComponentItem
                       ↑                 ↑
                  Settings          QUndoStack（整页快照）
                       ↓
                  PluginContext → 插件 Provider（插入组件 / 导出）
```

- **模型 → 画布**：切换页面时 `CanvasScene::loadPage()` 按页面数据重建图元
- **画布 → 模型**：`MainWindow::syncCanvasToModel()` 把场景里的组件写回页面
  （保存前、切页前、导出前、图层面板改动后都会同步）
- **撤销 / 重做**：`app/commands/PageSnapshotCommand`（QUndoStack）
  记录**整页组件列表快照**，撤销时把快照写回并重建场景
- **渲染统一入口**：所有绘制都走 `core/ComponentPainter`，编辑器、导出、对话框预览三者一致

## 4. 主窗口装配

`MainWindow`（`src/app/MainWindow.cpp`）是应用装配中心：

1. 创建 `PluginHost`，调用 `registerBuiltinPlugins()` 注册内置 Provider
2. 按 `PluginHost` 查询结果动态构建：插入菜单（遍历组件 Provider）、
   工具栏、导出格式下拉（遍历导出 Provider）、主题菜单（遍历主题 / 界面外观 Provider）
3. 创建左侧项目树、中间 `QStackedWidget`（画布 / 文章编辑器）、
   右侧 `QTabWidget`（素材库 / 图层），中间用 `QSplitter` 分隔
4. 持有 `ProjectManager`、`QUndoStack`、各面板与对话框，并负责它们之间的信号连接

## 5. 扩展点总览

所有扩展点通过 `plugin/PluginHost.h` 的 `PluginHost` 注册与查询，当前为
**编译时静态注册**（运行时动态库加载尚未实现）：

| 扩展点 | 接口 | 内置实现 |
| --- | --- | --- |
| 组件类型 | `IComponentProvider` | 13 个（图片 / 文本 / 表格 / 4 种形状 / 6 种贴纸） |
| 导出格式 | `IExportProvider` | 5 个（逐页 PNG、长图、文章 md / PNG / PDF） |
| 面板 / 视图 | `IPanelProvider` | **尚未接入**（内置面板仍由 `MainWindow` 直接创建） |
| 模板包 | `ITemplateProvider` | 1 个（转发 `TemplateManager::allTemplates`） |
| 主题（画布配色） | `IThemeProvider` | 1 个（内置「浅色页面」） |
| 界面外观 | `IUiStyleProvider` | 1 个（`GlassStyleProvider`：深色 / 浅色 / 跟随系统） |

接口签名、注册流程与扩展示例见 [插件开发](插件开发.md)。

## 6. 关键实现约定（改代码前必读）

- **组件数据变更必须走 `ComponentItem::applyComponentData()`**：统一负责「更新数据 →
  图片缓存按路径失效 → 重绘」。绕过它会出现「换了图但画布仍显示旧图」。
- **画布层序固定**：背景色矩形 `-2` < 页面背景图 `-1` < 组件（`zOrder` 自 1 起）。
  顺序写反会导致画布全白，`tests/editor/test_canvas_scene.cpp` 对此有回归保护。
- **页面背景图与卡片边框图存项目内相对路径**（`AssetStore::toProjectRelative`），
  图片组件例外（存绝对路径）。
- **对话框控件要先全部创建、再赋初值**：历史 bug 是构造期 `setValue` 触发回调访问了尚未
  创建的控件（导致闪退）并互相覆盖数据；`QSignalBlocker` + 空指针防御是既有约定。
- **`project.json` 写入用 `QSaveFile`** 原子替换；读取侧对尺寸有单边 16384px 的防线。
- 领域模型说明与更多实现记录见 [`docs/project-plan.md`](../docs/project-plan.md)。

## 7. 已知架构缺口

- 动态插件加载（`PluginHost::loadPlugins()`）只有 TODO 注释，无 `QPluginLoader` 代码
- `IPanelProvider` / `panelProviders()` 已定义但从未被消费
- `IComponentProvider::menuPath()` 目前只用于工具栏过滤，菜单是平铺的，没有按路径构建多级菜单
- `ThemeManager` 为静态硬编码，插件主题能进菜单但不会被真正纳入管理
- `ProjectManager::projectClosed` 信号已声明但从未 emit

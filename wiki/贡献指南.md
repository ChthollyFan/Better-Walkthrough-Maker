# 贡献指南

本页面向想改这个项目的人（包括未来的自己）。仓库根目录的
[`AGENTS.md`](../AGENTS.md) 是权威约定，本页是其摘要与索引。

## 1. 分支模型

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定分支，只接受发布合并 |
| `dev` | 日常开发分支，新功能先合到这里 |
| 特性分支 | 从 `dev` 切出，完成后合回 `dev` |

发布时：`dev` → `main`（`git merge --no-ff`）→ 打 tag → 推送；发布后把 `main` 合回 `dev`。
详见 [打包与发布](打包与发布.md)。

## 2. 提交与 PR

### 提交信息

使用 Conventional Commits，**主题行用中文祈使句**，不加句号，不超过 72 字符：

| 前缀 | 用途 |
| --- | --- |
| `feat:` | 新功能 |
| `fix:` | 缺陷修复 |
| `docs:` | 文档 |
| `refactor:` | 无行为变化的重构 |
| `test:` | 仅测试 |
| `chore:` | 维护类变更（构建脚本、版本号等） |

示例：`feat: 添加项目导出对话框`

### 拉取请求

- 一个 PR 只做**一个逻辑变更**，目标分支 `main`（或按当次约定指向 `dev`）
- 描述用中文说明：变更内容、原因、验证方式，并关联 issue
- 保持差异可审阅（理想情况下不超过 400 行）；UI 变更需附截图
- 请求评审前必须确保**构建与测试通过**

### 提交前必须确认

按照 `AGENTS.md`：**任何 git 提交 / 打 tag / 建 Release 之前，必须先列出方案
（涉及文件、提交信息）并取得明确确认**，文档改动也不例外。

## 3. 代码规范

完整规范见 [`docs/c++编码规范.md`](../docs/c++编码规范.md)（注意 `AGENTS.md` 里写的路径
`/docs/C++语言编码规范.md` 与实际文件名不一致，以实际文件为准）。核心约定：

### 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 类 / 结构体 | 大驼峰名词 | `CanvasScene` |
| 函数 | 小驼峰 | `handleMousePress` |
| 变量 | 小驼峰 + **类型前缀** | `nCount`、`bVisible`、`dScale`、`strTitle`、`vecPages`、`eType`、`pParent`、`rContext` |
| 类成员 | `m_` + 变量名 | `m_pScene` |
| 全局 / 静态 | `g_` / `s_` | `g_lTotal`、`s_pImage` |
| 枚举类型 / 值 | `E_` + 全大写下划线 | `E_COMPONENT_TYPE_TEXT` |
| 宏 | `DEF_` + 全大写 | `DEF_MAX_SIZE` |

禁止拼音，禁止仅靠大小写区分标识符。

### 排版

- 缩进 **4 空格，禁止 Tab**；行尾不留空格；单行 ≤ 80 字符
- `if` / `for` / `while` **必须带大括号**，关键字与括号紧贴：`if(xxx)`
- 类、函数的大括号另起一行
- 指针 / 引用符号紧贴变量名：`int* pVal`、`std::string& rStr`
- 禁止 `goto`，禁止魔鬼数字，变量定义即初始化，浮点禁止直接 `==`

### 注释与文件头

- 文件头需含 `@file` / `@author` / `@brief`
- 关键函数必须写注释（用途、参数含义、内存归属）
- 标记约定：`// TODO xxx`、`// DEBUG xxx`、`// NOTE xxx`，长循环块尾 `// end for`
- **重要或大型修改必须写注释说明**（`AGENTS.md` 要求）

### 改代码时的项目特有约定

- 组件数据变更一律走 `ComponentItem::applyComponentData()`（缓存失效 + 重绘）
- 画布层序固定：背景色矩形 `-2` < 背景图 `-1` < 组件（`zOrder` 自 1）
- 对话框要先创建全部控件再赋初值，并屏蔽初值触发的信号
- 新增导出参数请**追加在参数表末尾并给默认值**，保持第三方插件向后兼容
- 详细说明见 [项目架构](项目架构.md) 与 [`docs/project-plan.md`](../docs/project-plan.md)

## 4. 测试

- 测试放 `tests/`，目录镜像 `src/`，命名 `test_<单元>_<行为>`
- 新增行为要补测试，尤其是**错误路径**与**回归保护**（bug 修复应加一个能复现该 bug 的用例）
- 涉及文本渲染的测试用 `QTEST_MAIN`（需要 `QGuiApplication`）
- 提交前运行：

  ```powershell
  cmake --build build
  $env:PATH = "C:/Users/ThinkPad/Qt/6.11.2/mingw_64/bin;" + $env:PATH
  ctest --test-dir build --output-on-failure
  ```

## 5. 文档

- 使用者可见的行为变化 → 更新本 Wiki 对应页面
- 版本变更 → 更新 `CHANGELOG.md`（`## [未发布]` 段落）
- 设计层面的取舍 → 记入 `docs/project-plan.md` 的「实现记录」，包含踩坑原因与回归保护方式
- 新增插件类型 → 更新 `wiki/插件开发.md` 与 `docs/plugin-*.md`

## 6. 验证与交付

按 `AGENTS.md` 的约定：**每次修改后都要重新编译并生成单文件 exe**，交给实际使用者验证体验
（简单改动酌情执行）。打包命令见 [打包与发布](打包与发布.md)。
